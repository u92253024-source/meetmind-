## 2. 資料規格

### 2.1 `data.json` 結構

最外層為 JSON 陣列，每個元素代表一筆提案：

```json
[
  {
    "id": "t8u2n5q1k",
    "meetingName": "國立政治大學九十二學年度第一學期第一次教務會議紀錄",
    "unit": "英國語文學系",
    "title": "【提案一】增列成績計算辦法，特殊之科目可以「通過」及「不通過」為成績登錄。",
    "content": "案由：…說明：一、…辦法：一、…",
    "result": "決 議：本案經現場討論並以 45:0 通過，但於學則修定時應敘明…",
    "page": 8,
    "fileName": "92-1.pdf"
  }
]
```

### 2.2 欄位定義

| 欄位 | 型別 | 必填 | 說明 | 實測狀況 |
|------|------|:----:|------|----------|
| `id` | string | ✔ | 9 碼隨機英數字，全域唯一鍵 | 983 筆全數唯一，無重複 |
| `meetingName` | string | ✔ | 會議完整名稱，年度可為阿拉伯或中文數字 | 102 種不同值 |
| `unit` | string | ✔ | 提案單位 | 186 種寫法，其中 90 種僅出現 1 次 |
| `title` | string | ✔ | 案由標題，通常以`【提案N】`開頭 | 810 筆含`【提案`標記，其餘為臨時動議／復議案 |
| `content` | string | ✔ | 案由＋說明＋辦法之合併全文 | 平均 146 字，最長 762 字，最短 18 字 |
| `result` | string | ✔ | 決議內容 | 443 筆為 10 字以內的定型文（如「照案通過。」） |
| `page` | integer | ✔ | 提案在該 PDF 中的起始頁碼 | 範圍 1～48，全為合法整數 |
| `fileName` | string | ✔ | 對應 `pdf/` 內的檔名 | 98 個參照，與磁碟檔案 100% 對應 |

**資料完整性實測結果**：8 個欄位在 983 筆中皆無空值；`fileName` 無死連結、無大小寫不符
（`.pdf` 與 `.PDF` 混用但與磁碟完全一致，可安全部署於區分大小寫的 Linux 主機）。

### 2.3 資料特性與注意事項

1. **一個 PDF 可含多場會議**：5 份 PDF 各含 2 場會議
   （`98-4.pdf`、`100-3.pdf`、`102-3.pdf`、`107-4、連續.pdf`、`111-3.PDF`）。
2. **一場會議曾對應多個檔名（已修復）**：`95-3.pdf` 與 `95-臨時.pdf` 皆對應
   「95 學年度第 2 學期第 1 次教務會議暨臨時會議紀錄」，逐筆核對後確認 `95-臨時.pdf` 的 16 筆
   是 `95-3.pdf` 同批提案的精簡重複版（決議欄位無任何新資訊）。2026-08-11 已刪除 `95-臨時.pdf`
   的 16 筆，保留內容較完整的 `95-3.pdf`。`pdf/95-臨時.pdf` 檔案本身仍在，但已無紀錄引用。
3. **CJK 相容字元**：12 筆 `meetingName` 的「年」「度」使用 Unicode 相容字
   （U+F98E、U+FA01）而非常用字（U+5E74、U+5EA6），年度解析必須同時涵蓋兩者。
4. **PDF 內含前次會議決議執行情形**：會議紀錄通常先回顧前次會議各案的「執行情形」，
   再列本次提案。`data.json` **只收錄本次提案**，前次案件不重複收錄
   （已抽查 `105-1`、`99-2`、`113-1`、`95-3` 驗證此規則正確執行）。
5. **掃描影像檔**：`92-第二學期臨時.pdf` 為影像 PDF，無可抽取文字層。
6. **個資遮罩（2026-08-11）**：9 筆記錄、17 處欄位已完成遮罩——學生轉系／學位個案的姓名
   改為「姓＋○○」、完整學號刪除；1 筆身心障礙相關敘述同步改寫。
   規則、逐筆對照與判斷依據見 [REPORT.md](REPORT.md) 第 3.1 節；
   刻意保留未遮罩的公開職務具名連署紀錄亦說明於同節。

## 3. 功能規格

### 3.1 資料載入與前處理

系統啟動時 `fetch("data.json")`，載入後對每筆資料計算 6 個衍生欄位：

| 衍生欄位 | 計算來源 | 規則 |
|----------|----------|------|
| `year` | `meetingName` | 阿拉伯數字（`\d{2,3}學年度`）優先；中文數字（`九十二學年度`）次之；皆無則為`未知`。同時比對 CJK 相容字 |
| `semester` | `meetingName` | `第1/2學期` 或 `第一/二學期` → 1 或 2；無法判斷 → 9（排序時排最後） |
| `seq` | `meetingName` | 含「臨時」→ 99；否則取「學期」之後的`第N次`（支援中文數字）；無法判斷 → 9 |
| `proposalNum` | `title` | 取`【提案N】`之 N（支援中文數字）；無法判斷 → 9999 |
| `types` | `title` | 多標籤分類（陣列），見 3.2 |
| `searchText` | 7 個欄位 | `title + content + result + unit + meetingName + fileName + id` 以空白串接後轉小寫 |

中文數字轉換支援 1～99（`cnToInt`），不支援「百」以上，對 92～114 學年度足夠。

### 3.2 類型自動分類（多標籤，2026-08-11 修復）

`detectTypes(title)` 對每種類型**獨立比對**、互不排斥，回傳陣列；一個提案可同時符合多種類型
（如「申請修正○○辦法」同時歸入修訂與申請）。完全無命中時歸入「其他」。
篩選邏輯為 `item.types.includes(選定類型)`。

| 類型 | 觸發關鍵字 | 筆數（983 筆中，可重複計） | 占比 |
|------|------------|---------:|-----:|
| 修訂 | 修正、修訂、修訂案、條文修正、辦法修正、調整、修改、變更、廢止、廢除、停招、停止、終止 | 343 | 34.9% |
| 新增 | 新增、新設、新開、增設、設立、成立、訂定、擬訂、擬定、制定、簽訂、合作 | 302 | 30.7% |
| 報告 | 報告、提請核備、核備、工作報告、備查、追認 | 162 | 16.5% |
| 申請 | 申請、擬申請、申辦、續約 | 117 | 11.9% |
| 其他 | 以上皆未命中 | 259 | 26.3% |

> 修復前（固定優先序、單標籤）：其他 496 筆（49.6%），且「申請修正○○辦法」這類複合案由
> 只會被歸為修訂，查不到申請類。187 筆現具備多重標籤；殘留的「其他」259 筆多為缺乏明確
> 動作詞的純程序性決議案（課程委員會決議案等），未勉強硬塞分類。

### 3.3 搜尋邏輯

條件以 AND 組合：

```
年度相符（若有選）AND 類型相符（若有選）
AND 每一個正向關鍵字皆命中 AND 沒有任何排除詞命中
```

#### 查詢語法（`parseQuery()`）

| 語法 | 意義 | 範例 |
|------|------|------|
| 空白分隔 | 多關鍵字，**全部命中**才符合（AND） | `學則 修正` |
| `"詞組"` | 視為單一關鍵字（可含空白） | `"外語畢業標準"` |
| `-詞` | 排除，命中即剔除 | `通識 -遠距` |

- 全形引號 `「」` `“”` 與全形減號 `－` 會先轉為半角，避免中文輸入法造成查不到
- 比對方式：`searchText.includes(term)`，不分大小寫
- 所有條件皆空時不顯示結果（顯示提示文字，避免一次渲染 983 筆）
- 關鍵字輸入為 `input` 事件即時觸發，無延遲防抖（debounce）

#### 實測驗證

| 查詢 | 修改前 | 修改後 |
|------|-------:|-------:|
| `學則 修正` | 0 筆 | **16 筆** |
| `通識 學分` | 0 筆 | **72 筆** |
| `遠距 核備` | 0 筆 | **42 筆** |
| `通識` | 172 筆 | 172 筆（不變） |
| `通識 -遠距` | — | 151 筆 |
| `"外語畢業標準"` | — | 20 筆 |

### 3.4 排序規則

提供兩種排序，由「排序方式」下拉選單切換（`#sortMode`）：

| 模式 | 值 | 規則 |
|------|-----|------|
| 依相關度（預設） | `relevance` | `rankByScore()` 加權計分，同分退回時序排序 |
| 依年度時序 | `chrono` | `sortResults()` 四層排序 |

時序排序規則：

```
year 遞增 → semester 遞增 → seq 遞增（臨時會 = 99 排最後） → proposalNum 遞增
```

相關度計分（`rankByScore()`）：

| 欄位 | 權重 |
|------|-----:|
| 案由 `title` | ×5 |
| 內容 `content` | ×3 |
| 決議 `result` | ×2 |
| 單位 `unit` | ×1 |
| 會議 `meetingName` | ×1 |

多關鍵字時各詞分數累加；同分時退回年度→學期→次別→提案號，確保順序穩定。

> 未輸入關鍵字時（僅篩選年度或類型）相關度無意義，會**自動回退為時序排序**，
> 並在結果計數列標示實際套用的排序方式。

### 3.5 結果呈現

八欄表格：年度、會議、單位、案由、內容摘要、決議摘要、頁數、PDF。

| 項目 | 規格 |
|------|------|
| 每頁筆數 | 10 筆（`PER_PAGE`） |
| 摘要截斷 | `contextSnippet()`：以命中關鍵字為中心取前後約 45 字（keyword-in-context）；無關鍵字時退回開頭截斷前 90 字 |
| 關鍵字高亮 | 以 `<mark>` 標示，套用於案由、內容摘要、決議摘要；**多關鍵字同時高亮**（排除詞不高亮） |
| 分頁 | 上一頁／全部頁碼／下一頁，**一次渲染所有頁碼按鈕** |
| 全文檢視 | 點擊摘要開啟彈窗，以 `textContent` 輸出，保留換行 |
| PDF 連結 | `pdf/{encodeURIComponent(fileName)}`，`target="_blank"` |
| 換頁行為 | 換頁後平滑捲動回頁面頂端 |

> 2026-08-11 修復前：摘要固定顯示前 90 字，關鍵字出現在其後則該列完全看不到高亮
> （實測搜「通識」172 筆中 25 筆、「學則」40 筆中 8 筆受影響）。改為關鍵字前後文後已解決。

### 3.5a 分享與匯出（2026-08-11 新增）

| 功能 | 實作 |
|------|------|
| URL 分享狀態 | `syncUrlState()` 於每次搜尋後，把關鍵字（`q`）、年度（`year`）、類型（`type`）、
非預設排序（`sort`）寫入 URL query string，用 `history.replaceState`（不塞爆瀏覽器歷史）|
| 還原搜尋 | `loadUrlState()` 於 `init()` 時讀取 URL 參數並預填欄位；若有任何條件則自動執行搜尋 |
| CSV 匯出 | 「匯出目前結果為 CSV」按鈕，匯出 `filtered`（目前篩選後的全部結果，非僅當前頁），
欄位：年度／會議／單位／案由／內容／決議／頁碼／PDF 相對路徑；`\uFEFF` BOM 前綴確保 Excel 開啟中文不亂碼；
CSV 逸出處理欄位內逗號、引號、換行；無結果時彈出提示，不產生空白檔案 |

### 3.6 資安設計

| 機制 | 實作 |
|------|------|
| HTML 逸出 | 所有輸出欄位經 `escapeHtml()` 處理 `& < > " '` |
| 正規表示式逸出 | 關鍵字經 `escapeRegExp()` 後才組成高亮 regex |
| 彈窗輸出 | 使用 `textContent` 而非 `innerHTML` |
| 結論 | 資料與使用者輸入皆無法注入 HTML／腳本，無 XSS 破口 |

## 4. AI 助理規格（`indextest.html`）

`indextest.html` 在搜尋系統之外，加入名為 **MeetMind AI 助理** 的側欄聊天機器人。

### 4.1 架構

- 以 `<iframe>` 嵌入 Microsoft Copilot Studio webchat
- 端點形式：`https://copilotstudio.microsoft.com/environments/{環境ID}/bots/{機器人名稱}/webchat?__version__=2`
- `allow="microphone"`
- `sandbox="allow-scripts allow-same-origin allow-forms allow-popups allow-popups-to-escape-sandbox"`（2026-08-11 新增）：
  刻意不授權 `allow-top-navigation`（不能整頁跳轉）、`allow-modals`（不能跳原生對話框）、
  `allow-downloads`（不能觸發下載）；保留 `allow-same-origin` 是為了不讓聊天元件的對話狀態儲存機制失效
- `referrerpolicy="no-referrer"`（2026-08-11 新增）：避免把本頁網址透露給 Microsoft 網域
- 採**延遲載入**：首次開啟側欄時才把 `data-src` 寫入 `src`，避免拖慢首頁載入

> ⚠️ 環境 ID（tenant GUID）與機器人名稱硬編碼在前端 HTML 中，任何瀏覽網頁者皆可取得，
> 這點無法用程式碼修復——iframe 要嵌入就必須把網址送到瀏覽器端。真正的存取控制
> （僅限校內網域、需要登入）須在 Copilot Studio／Power Platform 後台的頻道安全性設定裡完成。

### 4.2 版面行為

| 裝置 | 行為 |
|------|------|
| 桌機（>1100px） | 側欄自右側推入，寬 420px，主內容區同步壓縮（flex 過場動畫 0.38s） |
| 平板（≤1100px） | 側欄寬度改為 360px |
| 手機（≤768px） | 側欄改為由底部展開，高度 70vh，覆蓋於內容之上；浮動按鈕移至側欄上方 |

### 4.3 用量控管（2026-08-11 加固，非完整修復）

| 參數 | 值 | 說明 |
|------|-----|------|
| `MAX_USAGE` | 30 | 每位使用者可用次數 |
| `COOLDOWN_SEC` | 20 | 關閉側欄後的冷卻秒數 |
| `SESSION_MAX_MINUTES` | 10 | 單次開啟逾時自動關閉的分鐘數（2026-08-11 新增） |
| `STORAGE_KEY` | `meetmind_usage_v1` | localStorage 與 cookie 共用的鍵名 |

行為流程：

1. 開啟側欄 → 剩餘次數 −1 → **同時寫入 localStorage 與 cookie**（效期 1 年）
2. 讀取剩餘次數時取 `Math.min(localStorage 值, cookie 值)`——清除其中一種儲存方式，
   另一種仍保留較低值，次數不會回滿（2026-08-11 新增）
3. 開啟後 10 分鐘若未關閉，自動觸發關閉（2026-08-11 新增），縮小「開一次問無限題」的曝險窗口
4. 剩餘 ≤10 次 → 次數標籤轉為警示色；≤5 次 → 轉為危險色
5. 關閉側欄 → 啟動 20 秒冷卻，期間浮動按鈕禁用並顯示倒數
6. 次數用盡 → 隱藏 iframe，顯示「使用次數已達上限」畫面，導引洽教務處分機 62441

文案（2026-08-11 修正）：「剩餘 N 次」→「剩餘 N 次**開啟機會**」，
用盡畫面加註「每次開啟可於 10 分鐘內詢問多個問題」，避免使用者或管理端誤解為逐訊息計費。

> ⚠️ **仍然存在、且無法只靠前端解決的限制**（已在程式碼註解中明確聲明）：
> 1. 純前端無後端架構下，使用者清除瀏覽資料（含 cookie）或使用無痕視窗仍可完全繞過限制，
>    這是架構層級的限制，不是實作疏漏。
> 2. Copilot Studio 的簡易 iframe 嵌入不會把訊息層級事件回傳給上層頁面（跨網域限制），
>    前端拿不到「使用者問了幾則訊息」，只能量測「側欄開了多久」——10 分鐘逾時自動關閉
>    只能縮小、無法消除「開一次問多題只算一次」的落差。
> 3. 若 Copilot Studio 依訊息數計費，唯一可靠做法是伺服器端驗證（Power Automate、
>    Azure Function，或 Copilot Studio 頻道本身的訊息上限設定），需要 Power Platform
>    後台存取權限，不在本次程式修改的範圍內。
